# Gemini + Vercel AI SDK Tool Routing

## Objective

Gemini is the reasoning and language layer.

The backend tool registry is the operational layer.

Use Vercel AI SDK to expose tools to Gemini.

Conceptual flow:

```text
User message
 ↓
Vercel AI SDK
 ↓
Gemini
 ↓
Tool selection
 ↓
Tool execution
 ↓
Structured ToolResult
 ↓
Gemini
 ↓
Text + UI actions
```

## Tool descriptions must be extremely explicit

Each tool description must tell Gemini:

- when to use it
- when NOT to use it
- required context
- whether it reads or writes
- whether confirmation is required
- what authority its output has

Example:

```ts
const applicationGetActionRequired = tool({
  description: `
  Get the actual applicant actions currently required for an application.
  Use this when the user asks what they need to do, what is missing,
  or whether they need to act.

  Do not infer actions from previous conversation.
  Do not fabricate action items.
  Always retrieve current application state.
  This is read-only.
  `,
  inputSchema: z.object({
    applicationId: z.string()
  }),
  execute: async ({ applicationId }, ctx) => {
    return applicationService.getActionRequired(
      applicationId,
      ctx
    );
  }
});
```

## Context injection

When the user is on:

```text
/applicant/projects/PRJ-123
```

the server should provide active context:

```text
activeProjectId = PRJ-123
```

When the user is on:

```text
/applicant/applications/APP-123
```

provide:

```text
activeApplicationId = APP-123
```

Gemini should not have to ask the applicant for identifiers already available from the current UI context.

## Tool routing examples

### User:
"What approvals do I need?"

Gemini should call:

```text
applicant_get_profile (if context incomplete)
project_get
approval_discover
```

Prefer `approval_discover` when projectId is already known.

---

### User:
"Why do I need this?"

Gemini should call:

```text
approval_get_applicability
knowledge_answer_with_sources
```

when a regulatory explanation requires source evidence.

---

### User:
"What am I missing?"

Call:

```text
application_get_action_required
```

or:

```text
application_get_workspace_context
```

Do not answer from memory.

---

### User:
"Find my GST certificate."

Call:

```text
document_search
```

Then:

```text
ui_open_document
```

---

### User:
"Can I submit?"

Call:

```text
application_xray
```

Then tell the user whether submission is ready based on actual state.

If ready, offer the submit UI.

Do NOT submit automatically.

---

### User:
"Submit this application."

Flow:

```text
application_validate
 ↓
show final summary
 ↓
user confirmation
 ↓
application_submit
```

---

### User:
"Book the earliest inspection."

Flow:

```text
inspection_get_available_slots
 ↓
show exact available slot
 ↓
ask user to select/confirm
 ↓
inspection_schedule
```

Never silently book an appointment.

---

# Structured assistant response

Gemini should be able to return:

```ts
interface AssistantResponse {
  message: string;
  citations?: ToolSource[];
  suggestedActions?: Array<{
    label: string;
    action:
      | "NAVIGATE"
      | "FOCUS_FIELD"
      | "OPEN_DOCUMENT"
      | "OPEN_APPROVAL"
      | "CONFIRM_WRITE";
    payload: Record<string, unknown>;
  }>;
}
```

The frontend executes only allow-listed UI actions.

## Do not allow arbitrary model-generated URLs

Navigation must use:

- route IDs
- entity IDs
- allow-listed route templates

Never execute arbitrary JavaScript or arbitrary URLs generated by the model.

## Streaming

Stream Gemini's textual answer.

Do not stream partial authoritative state.

Tool calls should complete first when the answer depends on live data.

For example:

```text
User: What am I missing?

tool call
 ↓
application_get_action_required
 ↓
result
 ↓
stream final answer
```

Do not stream:
"I think you might be missing..."
before the tool has returned.

## Tool parallelism

Safe independent READ tools may execute in parallel.

Example:

```text
profile
documents
notifications
```

For writes:

Never parallelize actions unless domain logic explicitly guarantees safety.

## Composite tools

Use composite tools to reduce latency.

For Home:

```text
applicant_get_home_context
```

For application workspace:

```text
application_get_workspace_context
```

For tracking:

```text
application_get_tracking_context
```

This is preferable to Gemini calling 8 independent tools every time a page loads.
